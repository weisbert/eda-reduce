# `.wv` 格式 & `wave_reduce` 设计约定（PLAN，未实现）

> 状态：**计划**。代码还没写。本文件定死格式、分工线、模块边界和不做的事，
> 下一轮按这个开工。

把 Cadence 波形（transient / AC / noise）压成一段能粘贴给大模型的紧凑文本，
带 Tkinter GUI 做参数调节和 reduce 前后对比预览。

是 `drawio_reduce.py` 的兄弟工具：那个压结构，这个压行为。

## 0. 北极星

> **项目的本质目的：把隔离区里的设计信息搬够，好在能跑大模型的机器上分析电路。**

`drawio_reduce`（结构）、`wave_reduce`（行为）、`plot_digitize`（兜底）都是这一个目的的手段，
不是独立的小工具。推论：

- **判断一个特性该不该做，标准是「模型分析电路时用不用得上」**，不是「压缩率高不高」。
  压缩率是约束，不是目标。丢一个模型需要的数是失败，多花 2 KB 带上一个关键测量是赚。
- **一次 debug 需要的是一组东西**：结构（`.rd`）+ 行为（`.wv`）+ 你的问题。
  格式设计上要能对得起来（同一个 case 里的信号名和 `.ckt` 的网络名要对得上）。
- **需求会一直长**。分析类型（电压/电流/PSS 谱/以后的谁知道）没法提前定义完，
  所以架构上要求：**核心通用、测量可插拔**（见第 9 节）。

## 0.1 第一性原理（这里和 `drawio_reduce.py` **不一样**）

`drawio_reduce` 的铁律是「脚本只做确定性变换，语义判断留给模型」，理由是不对称性：
脚本猜错了信息就没了，没人看得出来。

波形反过来：

> **脚本看得见全分辨率数据，模型永远看不见。**
> 凡是需要全分辨率才能算出的量（峰值的精确位置、周期抖动、settling time、
> spur 的 dBc、最大 slew），**脚本不算就永远丢了**——模型拿到 400 个点之后
> 再怎么聪明也算不回来。

所以分工线往下挪一格：

| | 谁做 | 为什么 |
|---|---|---|
| 抽点、量化、单位换算、重建误差自检 | 脚本 | 纯确定性 |
| **测量**：极值 / 过冲 / 上升时间 / settling / 周期抖动 / spur 频点与 dBc / 谐波比 | **脚本** | ← 与 `.rd` 的关键差异。需要全分辨率，丢了不可逆 |
| **判断**：这个过冲算不算问题、spur 是谁打进来的、要不要动补偿 | 模型 | 需要电路常识；模型猜错了你对着图能看出来 |

一句话：**脚本负责「测量」，模型负责「诊断」。脚本绝不写形容词。**
输出里不出现「轻微过冲」「看起来稳定」这类词——只有数。

## 1. 硬约束

| 约束 | 数值 | 来源 |
|---|---|---|
| 输出体积 | **≤ 20 KB** | 上行通道是聊天框，不是审美偏好 |
| 第三方依赖 | **允许**，但分层（见下） | 需求会长，部署方案必须能带外部库 |
| Python | 3.6+ | 隔离区机器的系统 python3 |
| `tkinter` | **已确认可用**（2026-07-27 实测） | 不再是风险项 |
| 波形数据落盘 | **一律 `private/`** | 波形编码设计性能，与电路图同级敏感 |
| 默认不输出 base64 blob | — | 跨边界前必须能用眼睛逐字审 |

### 依赖分层（代替原来的「零依赖」红线）

部署方案必须支持外部库（第 7 节的 full bundle 干这个）。但**分层仍然要守**：

| 层 | 依赖 | 理由 |
|---|---|---|
| `wave_core` / `wave_emit` / `wave_cli` | **纯标准库，硬性** | 单文件 scp 到任何机器就能跑，是永远的逃生舱；也让 incremental 包保持在几十 KB |
| `wave_metrics_*` | 优先标准库，可选 numpy 加速 | `import numpy` 失败要能退回纯 Python 路径，结果一致 |
| `wave_gui` | 允许（但预览画布用 `tk.Canvas`，见第 5 节） | GUI 是最可能长需求的地方 |

这不是妥协，是保险：核心不依赖任何东西，意味着哪天部署链坏了、或者要在一台
陌生机器上救火，`wave_core.py` + `wave_cli.py` 两个文件贴过去就能用。

## 2. 输出格式：`.wv`，三段

```
# WV1  tran  vco_core_tb  4 sig  t 0..300n  62738 -> 412 pts (152x)
# recon: max|err| 0.31 mV (0.35% of range) @ t=41.2n   rms 0.06 mV     <- 先看这行
# t [ns]                 0 .. 300.004        (quantized 1 ps)
# c1 V(vdd_pll) [mV]     offset +800.000     range -87.7..+0.4   (quantized 10 uV)
# c2 V(ctrl)    [mV]     offset +0           range 0..1200
# c3 I(mp0)     [uA]     offset +0           range 36.9..1957.7

[METRICS]                                    <- 全精度。别去 SHAPE 里量数
c1  min 712.334m @ 41.203n   max 800.423m @ 0.170n   pp 88.089m
c1  settle(+-1%) 187.4n   overshoot +2.1% @ 195.0n   slew_max -412 V/us @ 6.07n
c2  period 3.2894n   jitter pk-pk 14.2p  rms 3.1p  (N=91 cycles)
c2  rise(10-90) 88.1p   fall 91.4p   duty 49.7%
c3  mean 1.204m  rms_ripple 41.2u

[EVENTS]                                     <- 全精度时间轴，跨信号对齐看这里
41.203n   c1  GLOB_MIN   712.334m
41.9n     c2  EDGE_RISE  (thr 600m)
44.1n     c1  GLITCH     -3.2 mV, 1.8x local noise, width 210p
195.0n    c1  OVERSHOOT  +2.1%

[SHAPE]                                      <- 量化过，只用来看形状
0        31.93   0     36.9
0.1705   32.42   0     41.2
0.698    30.02   1200  55.1
...
```

三段的角色分工：`[METRICS]`/`[EVENTS]` 是**全精度的事实**，`[SHAPE]` 是**降精度的形状**。
头部第二行起是**自检**——输出声明自己的不确定度，等价于 `.ckt` 末尾那段推断标注。
`# WARN:` 排在 `# recon:` 前面：recon 说的是「我压得准不准」，
WARN 说的是「你这份输入根本撑不住下面的数」，后者更靠前一步。

## 3. 压缩链路：四步，每步独立可关

1. **预细化**（O(n)，扛 1e5–1e7 点）：任一信号相对上次保留点移动超过
   `0.3 * tol * range` 就保留，**并保留它前一个点（肩点）**。
   没有肩点，RDP 的弦会从平坦区直接切进凹坑，误差爆掉。
   （来自 `LDO_modeling/harness/decimate_trans.py` 的实测注释。）
2. **RDP**：用**垂直距离**而不是到弦的垂线距离（垂线在陡沿上欠分辨）；
   强制保留全局极值；eps 下限 = `tol`，让低于 tol 的噪声不吃点数预算。
3. **单位换算 + 基线扣除**：`1.70495e-10  0.800423`（21 B）
   → 时间换 ns、电压换 mV 并扣掉 800 mV 基线 → `0.1705 32.42`（11 B）。
   **在真实交付件上实测 22.0 → 12.1 B/行，1.83×**，而且更好读（没有满屏 `e-10`）。
4. **有效位数由容差推**，不拍脑袋：量化步长 ≤ RDP 的 eps / 4。
   既然已经接受了抽点误差，量化噪声压到它的 1/4 就够，再多的位数是纯浪费。

**振荡波形上预算是硬墙，参数拖不过去**（2026-07-28 实测补充）。SHAPE 是折线不是包络，
画一个正弦至少要 4~6 点/周期。2 µs 里 2515 个 5 GHz 周期 → 至少 15000 点 ≈ 150 KB，
20 KB 装不下，**把 max-points 拖到最大也没用**。三条天花板从里到外是：
预算 → 候选集上限（`--max-cand`，RDP 只能从候选点里挑）→ 波形本身的周期数。
最外面那条是信息量不是参数。所以：

- 工具要**说出**每周期几个点，低于 4 就报 `# WARN:`——不说的话它只是「不再变好」
- 要看波形就 `--xrange 1.6u:1.62u` 切一段：同样 20 KB，100 个周期能给 10 点/周期
- 窗口必须在头部 `# window:` 里声明，且 METRICS 的语义变成「窗口内」

预算核算：20 KB 里留 ~2 KB 给头部+METRICS+EVENTS，剩 18 KB / 12 B 行 ≈ 1500 行。
`csv2blob.py` 实测 800 个保形点能把 GHz 开关电流重放到 0.7 mV RMS——**体积不是瓶颈，
保真度才是**，所以第 2 节那条自检必须有。

## 4. spur 保护（频域路径）

频域数据在 RDP 之前，**强制保留**：所有比局部中位数底噪高 > X dB 的局部极大点，
外加它们的 HWHM 包络（`f0`，`f0 ± m*f0/(2Q)`，`m ∈ 0.05…4`）。

这条规则直接来自 `LDO_modeling/cadence/supply_noise/avdd_spectrum.py`，那边它是
**LOCKED** 的（有 `test_spur_sampling_rule.py` 守着）：实测漏采会把 353 nV 的 spur
报成 6.5 nV，低报 54×。同一个物理原因在这里成立——窄 spur 会被抽点直接跨过去。

spur 表输出频点、幅度、相对载波 dBc、**以及 `f/f0` 比值**。比值是确定性计算，
脚本给；「这是 DC-DC 二次谐波打进来的」是模型说。

## 5. GUI（Tkinter，纯标准库，不用 matplotlib）

存在的理由：**在数据所在的隔离机器上就把参数调好，避免"导出→传出→发现丢了特征→重来"的往返。**

```
┌ 上：原始 min/max 包络(灰带) + reduce 后曲线(红) ────────────┐
│   红线没跑出灰带 = 没丢东西                                  │
├ 中：误差曲线 = 重建值 - 原始值，横线标着容差   <- 关键窗格  │
│   一眼看出哪一段被削平了，而不是猜                           │
├ 下：[METRICS] 文本，全精度                                   │
└──────────────────────────────────────────────────────────────┘
实时读数：  412 点 │ 输出 11.3 KB │ max|err| 0.31 mV (0.35%) │ rms 0.06 mV
滑块：max-points ──o──   tol ──o──   [列选]  [强制保留: 极值/spur/事件] [纵轴跟视窗]
上窗格框选/滚轮缩放、右键拖平移、+/- ←/→、双击或 0 复位，中窗格跟随
```

**缩放时纵轴跟着视窗收**（默认开，可关成全局量程）。只放大横轴等于没放大：
一个 1.5 ns 的窗口里那段起伏可能只占全量程的 3%，按全局量程画出来还是一条直线。
纵轴半宽有个下限 `2 × eps`——视窗里什么都没发生时，尺度不该被容差以内的抖动撑开，
撑开了就会看见「红线到处跑出灰带」，像是这段被压坏了，其实全在容差里。
**判丢没丢东西看中窗格的 ±1**，那一格才是有刻度的；上窗格是形状。

**输出字节数随滑块实时更新**——这样是精确压到 20 KB，不是猜。

性能架构（没有 numpy 也要流畅，这条是硬要求）：

- **加载时跑一次 O(n) 预细化**（后台线程 + 进度条），产出几千个候选点；
- **之后所有交互只在候选集上做 RDP**，毫秒级；
- 灰带按画布像素列做 O(n) 预分箱（~1200 段），1e7 点也是瞬间画完；
- Canvas 上的线段总数恒定在 ~4000 以内。

**预览画布用 `tk.Canvas` 手画，不用 matplotlib**——理由是性能不是教条：
matplotlib 每次拖滑块要重画整个 figure，而这里要的是「拖动时字节数和误差实时变」。
Canvas 上就那 ~4000 条线段，改坐标即可，毫秒级。matplotlib 留给以后真正需要
它的场合（多子图报告、导出 PNG），不占这条交互路径。

## 6. 输入：只做 CSV

**不碰 PSF**（用户手动从 ViVA 导 CSV）。省掉 `binpsf.py` 那 ~250 行和整个二进制
格式的维护面。哪天真嫌导出烦了再加，`LDO_modeling/cadence/binpsf.py` 一直在那儿。

必须吃下的三种 ViVA 导出布局（**这条会咬人**）：

```
布局 A —— 共享 x 栅格（单条 trace，或同一次 sweep 的多条）
  time, V(out), I(mp0)
  0, 0.7999, 3.69e-5
  ...

布局 B —— 每条 trace 自带 x 列（不同 sweep 的 trace 叠在一张图上导出时）
  time, V(out), time, I(mp0)          <- 两个 time 列，长度可能不同！
  0, 0.7999, 0, 3.69e-5
  ...                    , 1.2e-9, 4.1e-5      <- 短的那列先空

布局 C —— ViVA「Export CSV」按钮的真实产物（2026-07-28 拿真文件撞出来的）
  v /gmp; tran (V) X, v /gmp; tran (V) Y
  0, 0.00076333
  3e-13, -0.00086388
```

布局 B 的判据：出现重复列名，或某列在中途开始出现空单元。
**解析器必须自动识别并拆成多条独立 trace**，不能把第二个 time 列当信号。

布局 C 是布局 B 的一个特例，但三处都不一样，要单独认：

- 每条 trace 两列 `<表达式> X`（横轴）/ `<表达式> Y`（纵轴），名字除后缀完全相同。
  **列名不重复**，所以布局 B 那条「重复列名」的判据认不出它
- 列名里自带**分号**。分隔符要是按「表头里哪个符号出现得多」认，会判成分号，
  然后整个数据区一行都切不出数 —— 判据必须换成「哪个候选能把**数据行**切成数字格」
- 括号里的单位是 **Y 的**（`(V)`），横轴其实是秒。照搬到 x 轴上量纲就错了。
  横轴的单位/类型从**分析名**（`; tran` / `; ac`）来；分析名认不出（比如 `pss`
  在 ViVA 里既可能出时域也可能出频域）就留 `unknown`，**不猜**

其它必须处理的脏数据：

- 重复时间点、非单调 t、NaN / `inf` / 空单元
- 表头行、单位行、ViVA 有时加的引号和尾逗号
- 频域导出的 y 可能已经是 **dB**（`dB20(...)` / `dB10(...)`）——头里带了就照搬，
  没带就标 `unknown`，**不猜、不换算**
- **dt 突然坍缩**（Spectre 收敛挣扎）——这本身就是 debug 信号，要报出来而不是静默跳过

## 7. 部署：三区管道，**两种包**

代码**下行**：

```
家 dev ──git push──▶ GitHub ──git pull──▶ 黄区 Win ──上传──▶ 隔离区
                                          package.ps1        bootstrap.sh / update.sh
```

因为要支持外部库，采用 **`weisbert/LDO_modeling/deploy/` 的双包模型**（已在真实
airgap 上跑通），叠上 **`weisbert/cadence-skill-tools` 的 git 卫生**：

| 包 | 内容 | 体积 | 什么时候用 |
|---|---|---|---|
| **full** | wheels + `requirements.lock` + app + `bootstrap.sh` | 大（有几个包就多大；只有标准库时几十 KB） | 首次安装、**依赖变了** |
| **incremental** | 只有 app 源码 + `update.sh` | ~几十 KB | 日常改代码（绝大多数时候） |

关键机制，一条都别省：

- **glibc 审计闸**：`audit_wheels.py` 在黄区就拒绝需要高于目标 glibc 的 wheel，
  并打印该降到哪个版本。不然错误要到隔离区才暴露，来回一趟成本极高。
  LDO_modeling 已验证过一组 cp311 / glibc-2.17 的版本组合，可直接抄。
- **依赖哈希闸**：`update.sh` 比对包里的 `requirements_hash` 和已部署 venv 的，
  不一致就**中止**并要求走 full。防止「改了依赖却只推了增量包」这类静默损坏。
- **`results/` 永不覆盖**，`.venv/` + `wheels/` 只建一次、被每次 update 复用。
- **git 卫生**（来自 cadence-skill-tools，同样必须有）：
  `.gitattributes` 里 `* text=auto eol=lf`——黄区是 Windows，没这条 `.py` 的 shebang
  会带 `\r`，到 Linux 上就是 "bad interpreter"；打包读 **committed blob** 而不是
  Windows 工作树，所以黄区的 autocrlf 设置污染不了包；`VERSION export-subst` 让
  隔离区用 `cat` 就能看到 commit + 日期，不需要 git。
- **备份 + 回滚**：部署前备份当前安装（留最近 3 份），替换过程中任何一步失败自动回滚。
- **用 `bash xxx.sh` 调，不要 `./xxx.sh`**——登录 shell 常是 tcsh，且上传通道可能掉 exec 位。
- **本地彩排**：在有 Docker 的机器上用 manylinux 镜像、断网、跑一遍 `--no-index`
  安装，证明离线装得上再往隔离区送（LDO_modeling 的 `dryrun_manylinux2014.sh`）。

> 目前依赖为空 → full 包也就几十 KB，两种包看起来没差别。**但管道现在就要按双包建**，
> 这样哪天加了 numpy，只是往 `requirements-gui.txt` 里加一行、重出一次 full 包，
> 而不是回头重做整条部署链。

数据**上行**方向完全不同：`.wv` 纯文本走聊天框。这就是 20 KB 的来源，
也是不默认输出 base64 blob 的来源（跨边界前要能用眼睛逐字审）。

`tkinter` 可用性已于 2026-07-27 在隔离区实测确认，不再是风险项。
（但它仍然**不能靠 wheel 补装**，见 memory `tkinter-not-shippable-as-wheel`——
以后换机器要重新确认。）

## 8. 明确不做（先写下来，防止以后手痒）

- **不在脚本里对变步长 transient 做 FFT**。Cadence 的自适应步长要先插值到均匀栅格，
  混叠风险由插值引入且不可见。要频谱就让 Cadence 出（`pnoise`/`pss`/ViVA `dft`），
  脚本只压缩结果。
- **不写形容词**（"轻微过冲"、"看起来稳定"）——那是模型的活。
- **不猜单位**。PSF 里有就带，ocnPrint 没有就写 `unknown`。
- **不做多 corner 家族压缩**（v2）。一族 7 条曲线各压一遍会撑爆预算；
  正解是「典型曲线全量 + 其余存与典型的差值」，差值很平所以点数极少。
- **不读 PSF**（见第 6 节）。
- **不让 `wave_core` 依赖任何第三方包**（见第 1 节的分层）。上层随便。
- **不默认输出 base64 blob**（见第 1 节）。

## 9. 架构：核心通用，测量可插拔

分析类型没法提前定义完（电压、电流、PSS 谱、以后的谁知道），所以边界这么切：

```
CSV ─▶ wave_core ────────────────────────────────▶ wave_emit ─▶ .wv
        解析 / 预细化 / RDP / 量化 / 重建自检          三段格式化
        对分析类型一无所知，只认「x 列 + y 列」            ▲
                                                         │
                    wave_metrics_*  ─────────────────────┘
                    每种分析一个模块，注册进一张表
                    tran / freq / dc / ...  以后随便加
```

- **`wave_core` 是通用的**：它只处理「一列 x + 若干列 y」，不知道 x 是时间还是频率。
  这一层做扎实，后面加分析类型就只是加一个 metrics 模块。
- **`wave_metrics_*` 按 kind 注册**：`register("tran", TranMetrics)`。
  新需求 = 新文件 + 一行注册，不动核心。
- **`.wv` 头里带 `kind`**，`[METRICS]` 段的行格式对每种 kind 自由，
  但必须是 `名字 值 单位` 的三元组形式，模型才好读。
- **x 轴是 log 还是 lin 由数据判定**（相邻点比值近似恒定 → log），
  影响 RDP 归一化的做法；这是 core 的事，不是 metrics 的事。

每完成一步就 commit，不要攒到最后——中途出意外也不至于全丢。

## 10. 方案二：截图数字化（`plot_digitize.py`，兜底）

不是方案一的替代，是**导不出数据时的兜底**，以及把已有的图（同事给的、报告里的、
datasheet 上的）变回可计算的数。

**物理上限就是像素。** 1920×1080 截图、绘图区高约 800 px：

| Y 轴量程 | 1 px | 亚像素质心后 |
|---|---|---|
| 1.0 V | 1.25 mV | ~0.4 mV |
| 100 mV（放大后） | 125 µV | ~40 µV |

有效 8–10 bit，相对满量程 0.1–0.3%。推论就是唯一重要的操作建议：
**截图的缩放层级就是量化器**——要看 5 mV 纹波，先在 ViVA 里把 Y 轴缩到 20 mV 再截图。

设计上绕开最脆的一环：**不做 OCR**，坐标范围手打（`--xaxis 0,300n --yaxis 0.7,0.81`），
绘图框自动找（最长的水平/垂直边框线）或手给。曲线按**颜色**提取（ViVA 每条 trace
颜色不同，这是最稳的一维）；每个 x 像素列取该颜色像素的**上下包络而不是中位数**，
这样密集振铃保留成一条带而不是被抽成锯齿。

输出头强制打上精度声明：

```
# PLOTDIG1  src=viva_zoom.png  plotbox 212,88..1687,901
# 精度上限: 1 px = 0.138 mV  (y 813 px / 0.112 V);  < 0.4 mV 的特征不可信
# trace #e01b24 -> vdd_pll   1475 列, 3 列无匹配像素(已线性补)
```

依赖：纯标准库（`zlib` 手解非隔行 8-bit PNG，约 60 行），有 Pillow 就用 Pillow。
理由同第 1 节。

**已知会挂的场景**（提前说清楚，别指望）：两条同色曲线交叉、对数轴上密集的噪声底、
半透明叠加、深色主题下网格线和曲线亮度接近。这些场景下工具应该
**报「该列有 N 个候选，无法判定」而不是猜一个**——同样是输出声明自己的不确定度。

**一句实话**：如果通道能贴图，定性问题（"这看着像不像振铃"）直接贴 PNG 更好。
数字化的价值在别处——把曲线变成**可计算**的东西：量振铃频率、两次跑的曲线相减、
拟合衰减包络、喂进后续脚本。以及在纯文本通道里，它是唯一的路。
