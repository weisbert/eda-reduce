# `wave_reduce` 实现时拍的板

`docs/wave-spec.md` 定了格式、分工线和模块边界。这里记的是 spec **没定**、
实现时必须做选择的地方，以及每个选择的理由。都可以推翻，推翻时看理由。

按「要不要回头改」的分量排序，前四条是真正影响结果的。

---

## 一、实测逼出来的四个设计（spec 没预见到）

### 1. eps 不能只由 tol 决定，要被噪声底兜住

`eps = max(tol × 量程, 3 × 噪声底)`，噪声底用三点弦偏差的 MAD 稳健估、
上限卡在量程的 10%。

**起因**：demo 里的 `V(vref)` 是一路几乎平的参考（0.8 mV 漂移 + 20 µV 噪声）。
它的「量程」本身主要就是噪声，`tol×量程 = 4.3 nV` 比噪声低三个数量级，
于是 RDP 一个点都删不掉——**在编码噪声，不是在编码信号**。
实测 2545 点只能压到 2335 点（1.1×）。

**代价**：这条通道的重建误差会顶到 3σ 附近（demo 里 13%）。这是物理下限，
再多的点也降不下去——所以 `.wv` 头里会写「← 已到该通道噪声底 X，
再多的点也降不下去」。

抬了 eps 一定进 `notes`。

### 2. 预细化要有候选点上限

同一条噪声通道让 O(n) 预细化失效：随机游走每一步都能越过一个小阈值，
候选集 ≈ 原始集，spec 第 5 节「交互只在候选集上做」的性能保证就没了
（实测 145k 点出 144k 候选）。

做法：候选数超上限（默认 20000）就整体放大阈值重扫，**放大倍数写进 notes**。
实测放大 7× 后出 17k 候选，0.08 s。

### 3. log 轴上重建必须按 `log(x)` 线性

RDP 在 log 空间切弦，自检要是按线性 x 量，报的是**另一条曲线**的误差。
demo_ac 上差了 40 倍（真实 0.37% vs 误报 15%）。
`.wv` 头里现在明写 `段间按 log(x) 线性内插`，读的人照着连线才对得上。

### 4. dt 坍缩的判据是「坍缩 **且** 信号没动」

spec 说 dt 突然坍缩是 debug 信号要报出来。直接实现会两头不讨好：

- 拿**全局**中位数当基准 → demo_tran 里 2 ps 的坍缩相对全局中位只有 7.5×，
  根本触发不了（因为时钟每 6.4 ns 加密一次，中位数被 15 ps 那一档带跑）
- 拿**局部**中位数 → 同样是 15 ps，还是不行
- 只看 dt 比值 → 求解器在陡沿上加密是它该干的事，会报出几十段假阳性

最后的判据：跟附近的**高分位** dt 比（「这一带本来能有多粗」），
连续小步数 ≥ 4，**且区间内所有信号的变化都没超出各自的噪声带**。
求解器在什么都没发生的地方原地踏步才是挣扎；沿上加密不是。
另一类只报个数不占篇幅。

## 二、格式上的选择

### 5. METRICS 一律带单位

spec 的示例写的是 `min 712.334m`（不带单位），但同一节的规则说
「必须是 名字 值 单位 的三元组，模型才好读」。按**规则**走，示例当笔误。

### 6. offset 用自己的词头单独打

spec 示例把 offset 打在列单位里。`V(vref)` 那种列是 `[uV]`，
offset 就会变成 `+600000.000 uV`。改成 `offset 600 mV`，列仍是 `[uV]`。

### 7. 词头按「哪个让每个数最短」选

20 KB 是硬约束。`1.2 V / 量化 1 mV` 写成 `[V]` 是 `1.200`（5 字节），
写成 `[mV]` 是 `1200`（4 字节）；600 行 4 列，一列省 1 字节就是 600 字节。
**x 轴例外**：留 2 字节余量换「自然」词头，因为 SHAPE 里的时刻要跟
METRICS/EVENTS 里的 `41.203 ns` 对着看，两边同一个数量级省事得多。

### 8. 量化步长取 10 的整数次幂（不取 1/2/5）

定点文本里只有 10 的幂真省字节：`q=2e-4` 和 `q=1e-4` 都要写 4 位小数。
代价是量化步长平均比目标细 3 倍左右，换来的是格式简单、位数确定。

### 9. 定点格式化后掐掉尾零

方波和平通道上省很多（`1200` 而不是 `1200.000`）。

### 10. 加了两行「读法」legend（约 150 字节）

北极星是模型读得懂。值这 150 字节。
**legend 正文里不写方括号形式的段名**——段标记的判据是「行首是 `[`」，
注释里出现一模一样的字样会让解析器（和模型）分不清哪一行才是真的段开始。
这个坑是实测踩到的。

### 11. 布局 B 的多条 trace 拼成一个 `.wv` 文档

每条自带完整头部，预算按条数均分。

### 12. `[EVENTS]` 上限 250 条，截断了在输出里说

时钟的沿不按时间顺序列前 8 个（对 debug 没用），列前 2 个定相位 +
**偏离均值最大的 3 个周期**，总数说清楚。

## 三、单位（spec：不猜单位）

### 13. 单位分三级：declared / inferred / unknown

spec 只说「有就带、没有就写 unknown」。但 `V(out)` 这种 ViVA 常见列名
全判 unknown，绝大多数真实文件就失去单位换算的收益了。
折中：从列名推的**照用但标记出来**（输出里带 `?`），
跟 `.ckt` 末尾的推断标注一个路子。`dB20(...)` 算 declared（函数名本身就是声明），
`V(...)` / `I(...)` 算 inferred。

### 14. 括号里是不是单位，只认白名单

`V(vco_out) (V)` 里 `vco_out` 是网络名不是单位。规则：括号内容落在 SI 单位
白名单里、或者 base 自己已经闭合了括号，才当单位；否则整串当列名。
猜错了整列的量纲就错了。

### 15. 加了 `--unit c1=V,x=s`

脚本不猜，人可以说。

### 15b. 分隔符按「哪个能把**数据行**切成数字」认，不按表头出现次数

（2026-07-28，真实 ViVA 文件逼出来的。原来是 `max(",;\t", key=head.count)`。）

真实的 ViVA 导出表头长这样：`v /gmp; tran (V) X,v /gmp; tran (V) Y` ——
分号在表头里出现 2 次、逗号 1 次，于是判成分号，数据行 `0,0.00076333`
一格数都切不出来，一路静默走到 `parse_csv` 返回 `[]`，
最后在 GUI 里表现成一句 `list index out of range`。

新判据：候选必须在表头里出现过（欧洲那种 `;` 分隔 + `0,5` 小数的文件靠这条
不会被逗号骗走），再看它把前 20 行数据切出多少个能 `float()` 的格。
数据行是纯数字的，切错了就切不出数——这是个**可判定**的判据，
不像数出现次数那样是启发式。

配套：解析不出任何 trace 时**抛异常并把证据摆出来**（判成的分隔符、表头几列、
数据首行切成几格），不再静默返回 `[]`。

### 15c. ViVA 的 `X`/`Y` 列对：横轴单位从**分析名**来，不从列名的括号来

同一次撞出来的第二件事。`v /gmp; tran (V) X` 里括号中的 `V` 是 **Y** 的单位，
横轴是秒。把它当 x 单位，整条时间轴的量纲就错了。

做法：认出成对的 `X`/`Y` 列（要求**每一列**都配得上对，否则不认），
把 X 列名改写成规范轴名（`; tran` → `time`、`; ac` → `freq`），
剩下的交给现成的「x 名字 → 单位/kind」规则。Y 列名去掉分析名后缀（`v /gmp`），
括号里的单位照旧走 declared 那条路。

`_VIVA_AXIS` 表**只列横轴能确定是什么的分析名**。`pss` 在 ViVA 里既可能出时域
也可能出频域，不猜——认不出就留 `unknown` 并在 notes 里说「用 `--kind` /
`--unit x=s` 声明」。`--xcols` / `--layout a` 优先于自动识别。

### 15d. 丢行超过 1% 报 `# WARN:`，排在 `# recon:` 前面

（2026-07-28，第二份真实文件逼出来的。原来只写一条 note。）

那份文件 423153 行，其中 302875 行（72%）是**重复时间戳**：ViVA 的 x 列只有
5 位有效数字，t≈1.6 µs 处的时间分辨率只剩 100 ps，而求解器步长约 5 ps。
工具照规则「重复点保留第一个」，等于把一个 5 GHz 的振荡按 10 GS/s 抽了样。
混叠出来的拍频包络**看着就像真实的起振包络**，而且拍周期会随频率牵引单调变短，
像极了一个物理过程。整件事当时只在第 7 行一条 note 里提了一句
「重复 x 点 302875 个，保留第一个」。

三条改动：

1. **`Trace.warn()` 和 `note()` 分家**。note 是「我做了什么」，warn 是
   「你手上这份数据别照着往下推」。十几条 note 里混着一条要命的，等于没说。
2. **WARN 排在 recon 之前**。recon 说「我压得准不准」，WARN 说「你这份输入
   根本撑不住下面的数」——一份 72% 的行被丢掉的文件，压得再准也没意义。
   文档里「头部第二行是自检」那句相应改成「第二行起」。
3. **WARN 要说清成因和怎么修**，而且是**可判定**地说：数 x 列文本写下来的
   有效数字位数（取一批行的最大值，`%g` 会去尾零所以单行会低估），
   末位就是那一带的时间分辨率。于是能直接说「x 列只有 5 位有效数字，
   2 µs 处分辨率 100 ps，平均步长 4.7 ps，重导时精度调到 12 位」。
   **验收标准就是这几行消失**——不用回来问人。

阈值 1%：零星几个重复点是求解器在断点上的正常行为（<0.1%），报了就是狼来了；
1% 以上一定是系统性的。抽样比报**最坏那一带**（分辨率随 |x| 变粗），
不报全文件平均——平均会把末段 21:1 的伤害稀释成 4:1。

### 15f. 振荡波形：报「点/周期」，加 `--xrange`，候选上限改成二分

（2026-07-28。起因是一句话：「max-points 拖到最大了，波形还是跟原数据差很多」。）

顺带先回答了另一半问题——**非均匀密度不用做，RDP 天生就是**。那份真实文件的
SHAPE 分布：0.1–1.3 µs 的死区花了 **1 个点**，99.3% 的点全在起振段。

「拖到最大还是不像」是三条天花板叠在一起，从里到外：

1. **预算**。20 KB / 12 B 一行 ≈ 1500~4000 行。
2. **候选集上限** `MAX_CAND=20000`。候选集是**质量上限**不只是性能参数：
   RDP 只能从候选点里挑，挑不到的形状后面加多少预算也回不来。
3. **波形自己的周期数**。这条是信息量，不是参数。

第 3 条最外层，也最容易被误当成 bug。所以加了 `carrier_warn`：数信号绕中线的
过零次数得到周期数（不做 FFT，见第 8 节），跟保留点数一比就是「点/周期」，
低于 4 报 WARN 并给出「要 xx KB」和「用 --xrange」。**报点/周期而不是误差百分比**：
误差百分比对振荡信号没有直觉（差半个周期就是 100%），点/周期直接对得上「像不像」。

过零计数的滞回取 `max(5% 量程, 3×噪声底)`。只用量程比例不行：一路纯噪声的平信号，
它的「量程」本身就是噪声的 ±4σ，5% 只有 0.4σ，实测 4000 点能数出 703 个假周期。

**候选上限的收敛改成二分**。原来是 `k *= max(1.6, len(keep)/max_cand)` 反复乘，
那条假设「候选数 ∝ 1/阈值」在噪声通道上大致成立，在振荡通道上完全不成立：
阈值一旦越过正弦的单步变化量，候选数断崖式塌到每周期两三个。实测 20 万点的
5 GHz 正弦，上限 20000 一步冲到 9448（3.76 点/周期，max|err| 75%）；
改成对 log(k) 二分后落在 18900（6.6 点/周期，62%）。**冲过头的那一半是白丢的分辨率。**
上限本身没动（GUI 的交互性能靠它），但加了 `--max-cand` 让命令行能开大，
并且把那条误导的 note（「噪声主导的通道会这样」）改成说清「候选集是质量上限」。

**`--xrange LO:HI` 落地**（原来在 backlog 🔵，因为这次有了实测数据才动手）：
同样 20 KB，全长 2 µs 是 4.0 点/周期、42% 误差；`--xrange 1.6u:1.62u` 是
10 点/周期、6.1% 误差（而且已经到噪声底）。切窗口在 `analyze` **之前**——
极值/噪声底/周期数都得是窗口内的，拿整条的极值定窗口内的容差会差出量级。
窗口一定在头部 `# window:` 声明，并 note 出「settle/final/drift 这类末态量
说的是窗口末态，不是仿真末态」——不写清楚模型会把局部当全局读。

GUI 同步：滑块拖到头时状态栏说**是哪条天花板在挡**（预算 / 候选集 / 周期数），
而不是默默地不再变好。

### 15e. `width 0 s` 不许打出来

同一份文件里的 `glitch1 -504.9 mV @ 1.691 us (width 0 s)`。宽度为 0 的跳变
不是物理量：它说的是「相邻采样点里没有一个落在半高以上，这个栅格解不出宽度」。
读的人（尤其是模型）会把它当成「一个无限陡的真实跳变」写进结论。
改成 `< 100 ps（该处采样解不出宽度）`——把「测不出」和「测出来是 0」分开，
前者是**该回去重导数据**的信号。

## 四、样例与真值

### 16. 六个夹具，不是两个

spec 第 0 步只要求 `demo_tran.csv` / `demo_ac.csv`。加了：
`demo_spec.csv`（PSS 谱，窄 spur 的家）、`demo_tran_layoutb.csv`
（布局 B 必须有夹具才测得了，spec 自己说这条「会咬人」）、
`demo_dirty.csv`（第 6 节列的脏数据）、`demo_tran_viva.csv`
（布局 C：`X`/`Y` 列对 + 列名里带分号的分隔符陷阱，见 15b/15c——
这个是拿真文件撞出来之后补的）。

### 17. 窄 spur 放在 `demo_spec.csv` 而不是 `demo_ac.csv`

AC 扫描（传递函数）里出现载波和 spur 物理上说不通。分开之后顺带把
「y 已经是 dB」和「y 是线性」两条路径都走到了。

### 18. 真值分「注入值」和「实际值」

洛伦兹线型的尾巴会互相叠加：载波在 2.5 GHz 处还有 -69 dBc 的裙边，
叠到 -52 dBc 的 spur 上就是 +1.14 dB。工具量到的是叠加后的值，
**这不是工具错**。所以 `demo_truth.json` 里两个数都存，测试对的是后者。

### 19. committed 的样例是 4000 点量级（~290 KB）

压力测试靠 `gen_demo_wave.py --scale 60` 现生成（7.6 MB，gitignore 掉）。
公开仓里塞 3 MB 的 CSV 不合适，但回归基线必须能逐字 diff。

## 五、流程与架构

### 20. CLI 精确压到预算，不是猜

先不限点数压一遍量出真字节数，拿到「头部 + METRICS + EVENTS」这块固定开销，
再二分 SHAPE 行数。只有首尾两次跑 O(n) 的重建自检
（为此给 `reduce_trace` 加了 `check=False`）。

### 21. 强制保留点优先于预算

spur 峰及其 HWHM 包络、极值、事件——为预算牺牲它们就等于回到
「低报 54 倍」那个坑。压不进去时**在输出里声明**超了多少、
强制点有几个、建议怎么办，而不是偷偷截断。

### 22. `Metrics` 钩子定成五个：prepare / analyze / forced / metrics / events

`prepare()` 允许改写信号——线性谱换 dB 这件事非做不可（载波 1 V、
底噪 -120 dBc 的谱，线性域 tol×量程 = 5 mV，而 -52 dBc 的 spur 只有 2.5 mV，
RDP 和量化会联手抹平）。改了必须 note。
`forced()` 在 RDP **之前**钉住必须保留的点。

### 23. 加了 `Metrics.suggest_tol()`

只有 metrics 层知道「这一段是噪声底，2 dB 就够了」这种事。
用户给了 `--tol` 以用户为准，没给才用建议值，且要 note 出来。

### 24. `wave_emit` 不 import 任何 metrics 模块

缺席照样出 `.wv`（只是没有 METRICS 段）。
`wave_core + wave_emit + wave_cli` 三个文件是永远的逃生舱，这条要守得住。
`tests/test_format.py` 里有 AST 扫描在守纯标准库这条线。

### 25. `wave_reduce.py` 是入口壳，逻辑在 `wave_cli.py`

对上 spec 第 9 节的模块表和 README 里的命令行。

## 六、GUI

### 26. 误差窗格按各信号**自己的 eps** 归一化

不管几路信号、什么单位，容差线永远是 ±1 那两根。
这是唯一能把 V / A / dB 画进同一个窗格的画法。

### 27. 拖动时只算抽样误差，松手 250 ms 后补算精确值

O(n) 的精确自检 145k 点要 0.5 s，每次拖动都算会卡手。

### 28. Canvas 列数按信号路数反推

spec 说「~1200 段」「总数 ~4000 以内」。四路信号照 1200 列画就是 9600 段。
改成 `列数 = 4000 / (2 × 信号数)`。

### 28b. 缩放时纵轴跟视窗，下限卡在 ±2 eps

（2026-07-28。原来横轴能框选缩放，纵轴恒按**全局**量程 `s.rng` 归一化。）

只放大横轴等于没放大：demo_tran 上一个 1.5 ns 的窗口，那段起伏只占全量程的 3%，
按全局量程画出来仍然是一条直线（实测纵轴尺度差 34 倍）。所以默认按**视窗内**的
原始包络定尺度，留一个开关能切回全局——比较不同时间段的绝对幅度时需要同一把尺子。

下限是 `半宽 >= 2 × eps`：视窗里什么都没发生时，尺度不该被容差以内的抖动撑开。
撑开了会看见「红线到处跑出灰带」，像是这一段被压坏了，其实全在容差里。
**丢没丢东西的判据在误差窗格的 ±1**（那一格有刻度），上窗格只管形状——
两格的分工因此更清楚了，不是一句补丁。

图例打的是**纵轴当前的上下限**而不是全局极值：放大之后这两个差着量级，
打错一个就会把局部幅度当成全局幅度读。

### 28c. 滚轮绑在 root 上按指针分派，Button-4/5 和 MouseWheel 都绑

Windows 的 `<MouseWheel>` 发给**有焦点的**控件而不是指针底下那个，绑在画布上会
时灵时不灵。X11 根本没有 `<MouseWheel>`，滚轮是 `<Button-4>` / `<Button-5>`。
隔离区是 Linux + X11，本机是 Windows——**只测得到一套，所以两套都绑**。
缩放锚在指针处（log 轴在 log 空间里做，线性做的话滚一格锚点就跑到几个 decade 外），
放大的下限用「视窗里还剩几个原始点」，不用绝对时间宽度：ps 级的 tran 和 MHz 级的
ac 上没有同一个合理的绝对值，点数有。

### 29. `--gui --selftest` 接管 Tk 的异常钩子

Tk 默认把回调异常打到 stderr 然后**继续跑 mainloop**，自检撞上就永远不退出
（第一版就是这么挂住的）。现在异常和超时都会立刻 destroy。

## 七、部署

### 30. 打包读 committed blob，不读工作树

`git archive HEAD`。黄区是 Windows，`core.autocrlf` 会把 `.sh` 变成 CRLF，
到 Linux 上就是 `bad interpreter: ...^M`；而且工作树里没提交的改动
打进包无从追溯。工作树脏时大声警告。

### 31. tar 里 mtime / uid 归零

同一个 commit 出同一个包，方便核对。

### 32. `requirements.txt` 是空的，管道照样按双包建

现在 full 和 incremental 看起来没差别。但哪天加 numpy，只是往
`requirements.txt` 加一行、重出一次 full 包，而不是回头重做整条部署链。

**文件名和 spec 第 7 节不一样**：spec 写的是 `requirements-gui.txt`
（那是从 LDO_modeling 搬过来的名字，那边确实只有 GUI 有依赖）。
这里没有「GUI 专属依赖」这个概念——GUI 用的 tkinter 根本装不了 wheel——
所以就叫 `requirements.txt`。

### 32b. 可选依赖单独放 `requirements-optional.txt`，不进打包流程

`requirements.txt` 是**被审计、被哈希、被冻进 lock** 的那一份。
往里加一行的代价是：重下轮子 + 过 glibc 审计闸 + **必须走 full 包**。

Pillow 只有 `plot_digitize` 用，而且缺了会自动退回自带的 zlib 解码器
（结果逐字节一致，有测试守着）。为这种东西把整条链拖下水、
让隔离区多背几 MB，不值。所以单独一个文件、明写「`package.py` 不读它」。

同理 tkinter **不写进任何 requirements**：写了也没用，pip 装不了，
只能上系统包。`bootstrap.sh` 会探一下并告诉你有没有。

## 八、截图数字化

### 33. 默认输出 CSV（带 `#` 精度声明），不直接出 `.wv`

README 画的链路是 `截图 → .wv`，但先出 CSV 再走 `wave_reduce`
能复用全部 metrics（振铃频率、包络拟合、两次跑相减都是 metrics 的活）。
`.wv` 那一步 `wave_reduce` 来做就行。

### 34. 每列输出**上下包络两列**，`--mid` 才给中线

密集振铃在一列像素里占几十个点，取中位数会得到上下乱跳的锯齿（假信号），
取包络得到一条带——**带是真的，锯齿不是**。
实测闭环：包络带外误差 1.07 px，中线 rms 0.86 px，但陡沿上中线能差 10.7 px。

### 35. 找不到绘图框就报错让人手给

不随便框一块然后把整张图的坐标都算错。
