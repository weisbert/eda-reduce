# `wave_reduce` 实现时拍的板

`docs/wave-spec.md` 定了格式、分工线和模块边界。这里记的是 spec **没定**、
实现时必须做选择的地方，以及每个选择的理由。都可以推翻，推翻时看理由。

按「要不要回头改」的分量排序，前四条是真正影响结果的。

---

## 一、实测逼出来的四个设计（spec 没预见到）

### 1. eps 不能只由 tol 决定，要被噪声底兜住

`eps = max(tol × 量程, 3 × 噪声底)`，噪声底用三点弦偏差的 MAD 稳健估、
上限卡在量程的 10%。

**起因**：demo 里的 `V(vref)` 是一路几乎平的参考（0.8 mV 漂移 + 20 µV 噪声）。
它的「量程」本身主要就是噪声，`tol×量程 = 4.3 nV` 比噪声低三个数量级，
于是 RDP 一个点都删不掉——**在编码噪声，不是在编码信号**。
实测 2545 点只能压到 2335 点（1.1×）。

**代价**：这条通道的重建误差会顶到 3σ 附近（demo 里 13%）。这是物理下限，
再多的点也降不下去——所以 `.wv` 头里会写「← 已到该通道噪声底 X，
再多的点也降不下去」。

抬了 eps 一定进 `notes`。

### 2. 预细化要有候选点上限

同一条噪声通道让 O(n) 预细化失效：随机游走每一步都能越过一个小阈值，
候选集 ≈ 原始集，spec 第 5 节「交互只在候选集上做」的性能保证就没了
（实测 145k 点出 144k 候选）。

做法：候选数超上限（默认 20000）就整体放大阈值重扫，**放大倍数写进 notes**。
实测放大 7× 后出 17k 候选，0.08 s。

### 3. log 轴上重建必须按 `log(x)` 线性

RDP 在 log 空间切弦，自检要是按线性 x 量，报的是**另一条曲线**的误差。
demo_ac 上差了 40 倍（真实 0.37% vs 误报 15%）。
`.wv` 头里现在明写 `段间按 log(x) 线性内插`，读的人照着连线才对得上。

### 4. dt 坍缩的判据是「坍缩 **且** 信号没动」

spec 说 dt 突然坍缩是 debug 信号要报出来。直接实现会两头不讨好：

- 拿**全局**中位数当基准 → demo_tran 里 2 ps 的坍缩相对全局中位只有 7.5×，
  根本触发不了（因为时钟每 6.4 ns 加密一次，中位数被 15 ps 那一档带跑）
- 拿**局部**中位数 → 同样是 15 ps，还是不行
- 只看 dt 比值 → 求解器在陡沿上加密是它该干的事，会报出几十段假阳性

最后的判据：跟附近的**高分位** dt 比（「这一带本来能有多粗」），
连续小步数 ≥ 4，**且区间内所有信号的变化都没超出各自的噪声带**。
求解器在什么都没发生的地方原地踏步才是挣扎；沿上加密不是。
另一类只报个数不占篇幅。

## 二、格式上的选择

### 5. METRICS 一律带单位

spec 的示例写的是 `min 712.334m`（不带单位），但同一节的规则说
「必须是 名字 值 单位 的三元组，模型才好读」。按**规则**走，示例当笔误。

### 6. offset 用自己的词头单独打

spec 示例把 offset 打在列单位里。`V(vref)` 那种列是 `[uV]`，
offset 就会变成 `+600000.000 uV`。改成 `offset 600 mV`，列仍是 `[uV]`。

### 7. 词头按「哪个让每个数最短」选

20 KB 是硬约束。`1.2 V / 量化 1 mV` 写成 `[V]` 是 `1.200`（5 字节），
写成 `[mV]` 是 `1200`（4 字节）；600 行 4 列，一列省 1 字节就是 600 字节。
**x 轴例外**：留 2 字节余量换「自然」词头，因为 SHAPE 里的时刻要跟
METRICS/EVENTS 里的 `41.203 ns` 对着看，两边同一个数量级省事得多。

### 8. 量化步长取 10 的整数次幂（不取 1/2/5）

定点文本里只有 10 的幂真省字节：`q=2e-4` 和 `q=1e-4` 都要写 4 位小数。
代价是量化步长平均比目标细 3 倍左右，换来的是格式简单、位数确定。

### 9. 定点格式化后掐掉尾零

方波和平通道上省很多（`1200` 而不是 `1200.000`）。

### 10. 加了两行「读法」legend（约 150 字节）

北极星是模型读得懂。值这 150 字节。
**legend 正文里不写方括号形式的段名**——段标记的判据是「行首是 `[`」，
注释里出现一模一样的字样会让解析器（和模型）分不清哪一行才是真的段开始。
这个坑是实测踩到的。

### 11. 布局 B 的多条 trace 拼成一个 `.wv` 文档

每条自带完整头部，预算按条数均分。

### 12. `[EVENTS]` 上限 250 条，截断了在输出里说

时钟的沿不按时间顺序列前 8 个（对 debug 没用），列前 2 个定相位 +
**偏离均值最大的 3 个周期**，总数说清楚。

## 三、单位（spec：不猜单位）

### 13. 单位分三级：declared / inferred / unknown

spec 只说「有就带、没有就写 unknown」。但 `V(out)` 这种 ViVA 常见列名
全判 unknown，绝大多数真实文件就失去单位换算的收益了。
折中：从列名推的**照用但标记出来**（输出里带 `?`），
跟 `.ckt` 末尾的推断标注一个路子。`dB20(...)` 算 declared（函数名本身就是声明），
`V(...)` / `I(...)` 算 inferred。

### 14. 括号里是不是单位，只认白名单

`V(vco_out) (V)` 里 `vco_out` 是网络名不是单位。规则：括号内容落在 SI 单位
白名单里、或者 base 自己已经闭合了括号，才当单位；否则整串当列名。
猜错了整列的量纲就错了。

### 15. 加了 `--unit c1=V,x=s`

脚本不猜，人可以说。

## 四、样例与真值

### 16. 五个夹具，不是两个

spec 第 0 步只要求 `demo_tran.csv` / `demo_ac.csv`。加了：
`demo_spec.csv`（PSS 谱，窄 spur 的家）、`demo_tran_layoutb.csv`
（布局 B 必须有夹具才测得了，spec 自己说这条「会咬人」）、
`demo_dirty.csv`（第 6 节列的脏数据）。

### 17. 窄 spur 放在 `demo_spec.csv` 而不是 `demo_ac.csv`

AC 扫描（传递函数）里出现载波和 spur 物理上说不通。分开之后顺带把
「y 已经是 dB」和「y 是线性」两条路径都走到了。

### 18. 真值分「注入值」和「实际值」

洛伦兹线型的尾巴会互相叠加：载波在 2.5 GHz 处还有 -69 dBc 的裙边，
叠到 -52 dBc 的 spur 上就是 +1.14 dB。工具量到的是叠加后的值，
**这不是工具错**。所以 `demo_truth.json` 里两个数都存，测试对的是后者。

### 19. committed 的样例是 4000 点量级（~290 KB）

压力测试靠 `gen_demo_wave.py --scale 60` 现生成（7.6 MB，gitignore 掉）。
公开仓里塞 3 MB 的 CSV 不合适，但回归基线必须能逐字 diff。

## 五、流程与架构

### 20. CLI 精确压到预算，不是猜

先不限点数压一遍量出真字节数，拿到「头部 + METRICS + EVENTS」这块固定开销，
再二分 SHAPE 行数。只有首尾两次跑 O(n) 的重建自检
（为此给 `reduce_trace` 加了 `check=False`）。

### 21. 强制保留点优先于预算

spur 峰及其 HWHM 包络、极值、事件——为预算牺牲它们就等于回到
「低报 54 倍」那个坑。压不进去时**在输出里声明**超了多少、
强制点有几个、建议怎么办，而不是偷偷截断。

### 22. `Metrics` 钩子定成五个：prepare / analyze / forced / metrics / events

`prepare()` 允许改写信号——线性谱换 dB 这件事非做不可（载波 1 V、
底噪 -120 dBc 的谱，线性域 tol×量程 = 5 mV，而 -52 dBc 的 spur 只有 2.5 mV，
RDP 和量化会联手抹平）。改了必须 note。
`forced()` 在 RDP **之前**钉住必须保留的点。

### 23. 加了 `Metrics.suggest_tol()`

只有 metrics 层知道「这一段是噪声底，2 dB 就够了」这种事。
用户给了 `--tol` 以用户为准，没给才用建议值，且要 note 出来。

### 24. `wave_emit` 不 import 任何 metrics 模块

缺席照样出 `.wv`（只是没有 METRICS 段）。
`wave_core + wave_emit + wave_cli` 三个文件是永远的逃生舱，这条要守得住。
`tests/test_format.py` 里有 AST 扫描在守纯标准库这条线。

### 25. `wave_reduce.py` 是入口壳，逻辑在 `wave_cli.py`

对上 spec 第 9 节的模块表和 README 里的命令行。

## 六、GUI

### 26. 误差窗格按各信号**自己的 eps** 归一化

不管几路信号、什么单位，容差线永远是 ±1 那两根。
这是唯一能把 V / A / dB 画进同一个窗格的画法。

### 27. 拖动时只算抽样误差，松手 250 ms 后补算精确值

O(n) 的精确自检 145k 点要 0.5 s，每次拖动都算会卡手。

### 28. Canvas 列数按信号路数反推

spec 说「~1200 段」「总数 ~4000 以内」。四路信号照 1200 列画就是 9600 段。
改成 `列数 = 4000 / (2 × 信号数)`。

### 29. `--gui --selftest` 接管 Tk 的异常钩子

Tk 默认把回调异常打到 stderr 然后**继续跑 mainloop**，自检撞上就永远不退出
（第一版就是这么挂住的）。现在异常和超时都会立刻 destroy。

## 七、部署

### 30. 打包读 committed blob，不读工作树

`git archive HEAD`。黄区是 Windows，`core.autocrlf` 会把 `.sh` 变成 CRLF，
到 Linux 上就是 `bad interpreter: ...^M`；而且工作树里没提交的改动
打进包无从追溯。工作树脏时大声警告。

### 31. tar 里 mtime / uid 归零

同一个 commit 出同一个包，方便核对。

### 32. `requirements.txt` 是空的，管道照样按双包建

现在 full 和 incremental 看起来没差别。但哪天加 numpy，只是往
`requirements.txt` 加一行、重出一次 full 包，而不是回头重做整条部署链。

## 八、截图数字化

### 33. 默认输出 CSV（带 `#` 精度声明），不直接出 `.wv`

README 画的链路是 `截图 → .wv`，但先出 CSV 再走 `wave_reduce`
能复用全部 metrics（振铃频率、包络拟合、两次跑相减都是 metrics 的活）。
`.wv` 那一步 `wave_reduce` 来做就行。

### 34. 每列输出**上下包络两列**，`--mid` 才给中线

密集振铃在一列像素里占几十个点，取中位数会得到上下乱跳的锯齿（假信号），
取包络得到一条带——**带是真的，锯齿不是**。
实测闭环：包络带外误差 1.07 px，中线 rms 0.86 px，但陡沿上中线能差 10.7 px。

### 35. 找不到绘图框就报错让人手给

不随便框一块然后把整张图的坐标都算错。

## 已知没做 / 做不到

- **断网彩排没跑过**：本机没有 docker。`deploy/dryrun_manylinux2014.sh`
  写好了，它在没有 docker 时明确说「跳过」并 exit 2，不假装通过。
  **往隔离区送之前必须在有 docker 的机器上跑一遍。**
- **隔离区实机没验过**：`bootstrap.sh` / `update.sh` 是在 Windows 的 Git Bash 上
  端到端跑通的（含回滚）。真机上的 tcsh 登录 shell、掉 exec 位、
  系统 python3 版本这些只能到现场确认。
- **谱的 SHAPE 段仍然偏胖**（demo_spec 969 点 / 15 KB）：噪声底是非平稳的
  （载波裙边区光滑、远端是 Rayleigh 起伏），全局一个 eps 会在起伏区多花点数。
  在预算内且自检诚实，但不够漂亮。正解是按区间给 eps，没做。
- **多 corner 家族压缩没做**（spec 第 8 节列为 v2）。
- **不读 PSF**（spec 第 6 节明确不做）。
